# Eval ingest contract

Delegates fill cards. They do not edit this file.

A LoCoMo win is not a companion memory system. Most public benches score retrieve-then-QA. That is why vendors look interchangeable.

## Shared premise to test, not assume

If we retrieve the right past text or extracted facts into the prompt, the model will act as if it remembers the relationship.

An eval that only asks a probe at the end of a haystack assumes that sentence.

## Bands

`research/evals/registry.json` is the index. Every listed id must appear.

- `already-carded`. Slice F. Do not rewrite those cards unless a primary source changed.
- `core`. Could be used to select a companion store, or vendors cite it as if it did. Gets a census card `kind=eval-benchmark`.
- `adjacent`. Steal one idea. No card. One `steal` sentence.
- `out-of-scope`. GPU safety, robot process memory, coding-agent hygiene. One `why_band` sentence.

Do not promote RULER or NIAH to `core`. They are long-context needles, not companions.

## Card rules

Same schema as `research/_contracts/card.schema.json`. `kind` is `eval-benchmark`.

In `ontology_notes` name the user modeled (friend-chat, assistant, RP character, web agent, scientist). Name what the metric scores. Name which of the ten companion holes it misses.

`companion_fit` here means would this eval select a good companion memory system. FIT only if it scores identity drift, silence, and poisoning. None of the public set will be FIT. Do not inflate.

Primary sources only. Paper HTML or GitHub README plus LICENSE. Vendor blogs are `guess`.
